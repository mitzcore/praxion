# Audit of Praxion, 2026-11-02

Requested by Mithran before the hardware run and the submission: "review and audit the work we did for Praxion, tell me if you find any flaw, error, corrections required in code, the concept, logic and the TCLab kit code for testing including the test results, outcome and judgement we made."

Method: four independent reviewers (fresh context, no access to our conclusions) attacked one area each with runnable evidence, plus a statistics pass on the stored bundles. Nothing was graded by the author. Judges used: independent re-computation of every published metric from the stored traces with code that imports nothing from `backend.evaluation`; the vendor `tclab` library as the serial-protocol ground truth; a fake TCLab board speaking that protocol driving the real `scripts/run_live_demo.py`; a scan of every stored prompt (`model_calls.jsonl`) and view snapshot against each run's hidden state; sign tests and exact binomial intervals on the headline counts; the test suite.

Outcome in one line: **the published numbers reproduce exactly; the hardware path had three defects that would have wasted today's run or left the heater on, now fixed; the blindness claim was overstated in two ways, one of which contaminates the thermal-simulator diagnosis scores; the evaluator cache could have served stale scores.** Everything below is either fixed in this commit, scheduled with a named trigger, or disclosed in the README.

## 1. What held

- **Every published metric recomputes.** For runs `v13-s11`, `v13-s14` and `spark2`, independent code recomputed per-episode MAE, in-band fraction, hard violations, overrides, median reduction and the G2/G3 verdicts from the stored traces. All match the stored aggregates and `docs/BENCHMARKS.md` to 1e-12.
- **Same-seed guarantee holds.** v1 and v2 in every run were scored on byte-identical scenarios: same initial level, same hidden parameters, same disturbance delay and magnitude, noise identical to 1.1e-16.
- **Gate code matches the README text.** Bounds inclusive as documented, NaN treated as failure, G2 requires zero overrides, G3 requires zero hard violations and zero invalid outputs. No promoted repair had any post-change override, so the fact that G3 permits overrides never helped a repair pass.
- **Physics.** Forward Euler is stable across the whole parameter range (dt/tau ≤ 0.10); the outflow law is √h and steady states match analytically; the actuator lag is a true transport delay then a first-order lag; the plant, scenario and noise streams are independent (two controllers on one scenario see identical noise). Every disturbance family switches on at exactly 60 s and persists. `TCLabSim` matches the vendor `TCLabModel` to 4.7e-13 °C.
- **Monitor.** 0 false alarms in 2520 nominal episodes across six controllers on exploration seeds, 0/360 on offset families, 120/120 lag detections. Consistent with the status doc.
- **Blindness, numeric.** Every stored prompt and view of all 23 runs was compared against that run's hidden parameters, scenario seeds, twin fits and disturbance magnitudes, with perturbed-value controls. No `h_true`, no parameter name, no baseline score, no seed reached the model.
- **Sandbox and checker.** Unicode-normalised names, `getattr`/`type()`/decorator/`yield` tricks, `.format` and f-string tricks: all rejected or neutralised; the one that passed static check (`gi_frame` walk) was blocked by the runtime audit hook. Host-side parsing rejects non-finite, boolean and non-numeric outputs.
- **Serial protocol.** `TCLabHardware` uses the vendor `tclab.TCLab` class directly: 115200 baud with 9600 fallback, `\r\n`, 2 s timeout, `VER` handshake, Q2 held at 0, `Q1 = 100·u` validated and clipped; the 1 s tick is kept against a monotonic schedule.
- **Head-to-head window is apples to apples.** Praxion v2 and the re-tuned relay PI both run as fixed controllers from t = 0 on the same five scenarios; post-change MAE covers 60 to 300 s for both. Neither window includes identification time; that is reported beside the scores, not charged to them.

## 2. Findings and what was done

Severity: **critical** = would waste the hardware run, damage the board or mislead a judge; **high** = a claim or score could be wrong; **medium** = a real gap with contained impact; **low** = wording, counts, comments.

### 2.1 Hardware path (TCLab), all fixed in this commit, verified on the fake board

| # | Finding | Fix |
|---|---|---|
| C1 | The 30-minute wall-clock budget stopped every full fake run in ADAPTING ("wall clock budget exhausted"). A real run takes 60 to 75 minutes; simulator rehearsals hid this because simulated time costs no wall time. | `run_live_demo.py` sets a 3 h budget for `--plant tclab`; `--max-wall-clock-s` overrides. |
| C2 | The heater stayed on after a normal exit, SIGTERM or SIGHUP (closing the terminal). The exit hook held boards in a `WeakSet` and the object was usually collected before the hook ran. The firmware does not help: its 50 °C alarm only blinks the LED. | Strong set; `try/finally plant.close()`; SIGTERM and SIGHUP raise `SystemExit`. |
| C3 | Nothing stepped the plant between stages: the last experiment's or controller's command was held open-loop through authoring, gating and model calls. On the fake board T1 climbed 45.9 → 53.6 °C at a fixed 55 % during 440 s of gating. The worst approvable case settles near 80 °C. | Orchestrator idles the actuator (`emergency_stop`) after discovery, after the monitored rollout, after re-identification and at the end of the run, on physical plants only; event `actuator_idled`. |
| H1 | One missed or garbled serial reply ended the hour-long run with an uncaught exception and a bundle stuck at `stage: MONITORING`. | `TCLabHardware` retries reads and writes three times with an input-buffer flush; the orchestrator catches any plant or runtime fault, records it, and marks the run FAILED. |
| H2 | While the operator prompt waited for Enter, no control ran: the heater held its last command and the time was not recorded. A late Enter produced a 13 °C jump between two consecutive trace samples. | The prompt is non-blocking: a thread waits for Enter while the control loop keeps running; the first tick after Enter is the recorded disturbance time (`operator_disturbance_applied`, `t`). |

Fake-board verification after the fixes (`scratchpad/hw/go.sh retest`, mock agent, no network): discovery → twin fit → G2 → deploy → prompt → monitor fires 69 s after the fan → re-identification → changed twin → v2 promoted → COMPLETE; actuator idled four times; board report at process exit `Q1=0.0, stopped=true`.

Still open on hardware, disclosed: the stale-sensor check in the supervisor can never fire because every caller passes plant time as "now" (also true in simulation); hardware time is a tick counter. The fan may not trip the monitor if the controller is good and the fan weak (a 20 % loss increase peaks at 1.17 °C error against the 1.2 °C floor); the pre-flight in the runbook measures the fan first. The twin-fit warnings miss a warm or still-cooling board (fitted ambient off by up to 5 °C with no warning); the runbook now requires a cold board.

### 2.2 Trust boundary

| # | Finding | Status |
|---|---|---|
| H3 | **The run id reached the model.** Candidate ids are `<run_id>-vN` and were shown in the view and in gate-reason feedback. The run id carries the operator's `--label`, so the thermal-simulator runs told Muse "fan" or "weak" in the adapting and re-identifying prompts, and the tank runs carried the plant seed digits ("s11"). The leak scanner did not catch it because those words are not in its forbidden list. | **Fixed.** The model sees opaque ids ("v1", "v2") everywhere, including gate reasons; the run id is a scanned secret; the full message list is scanned, not only the view (the model's own source is exempt); new tests, including one over every stored prompt of every run. **Consequence disclosed:** the diagnosis-correctness results of the `tclabsim-fan*` and `tclabsim-weak` runs are contaminated and are no longer cited as evidence that Muse diagnosed the thermal change blind. The tank runs leaked only a seed number, which carries no information without the simulator. Today's hardware run uses a neutral label. |
| H4 | **"Hidden scenarios the model never sees" was too strong.** After a failed G2 attempt, and before every G3 revision, the model receives measured (noisy) traces and summaries of the scoring episodes; the revised controller is then scored on those same episodes. Up to three repair attempts run against one fixed five-scenario gate. | **Disclosed** in the README; the protocol fix (a third seed set never shown to the model, used only for promotion) is a frozen-config change and goes in the next version, not this submission. |

Muse diagnosed from those traces. The relay rival's after-change phase used the same rollout. | **Fixed** in `monitor.py` (routes through the runtime's `_apply`). Recorded bundles are unchanged, as they must be; the benchmark re-score under the new fingerprint picks up the relay's side. |
| L1 | The seed regex exempts floats (`1000.0`), by design for TCLab trace times. | Noted. |

### 2.5 Statistics of the headline claims

- Relay wins post-change MAE 11/12: two-sided sign test p = 0.006; 8/9 among runs with a real repair, p = 0.02 one-sided; 4/5 among v1.3 runs, p = 0.19.
- Protocol v1.3 5/5: exact 95 % interval [0.48, 1.0].
- The G3 rule (≥ 3 of 5 scenarios improved ≥ 20 %) passes with probability 0.68 if each scenario independently improves with probability 0.6, and 0.84 at 0.7. The G2 rule (8/10) passes with 0.38 at a true per-episode rate of 0.7 and 0.93 at 0.9. Five scenarios cannot certify a repair; this is the first parameter to raise.

## 3. What a top expert would still do next

1. Run protocol v1.3 on five fresh plant seeds it was never tuned on, and report that distribution beside the in-sample one.
2. Add a third seed set, never shown to the model, used only for promotion; raise it to 10 scenarios.
3. Fix the relay's ultimate-point identification and re-score the rival at full strength.
4. On hardware, add a true-time staleness check and a hardware-truth comparison: v1 then v2 on the physical plant with the fan on, same window, reported as measured error.
