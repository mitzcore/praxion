# Provenance

## Who wrote what

All code in this repository was written during the hackathon window, October 30 to November 4, 2026, by Mithran Selvaraj with AI coding assistants (Claude). Mithran set the objective, made the scope and design decisions, and reviewed the work. Claude wrote most of the implementation from those decisions and ran the tests.

## Model-authored artifacts

Every `controller_v*.py` file under `artifacts/runs/<run_id>/` is a verbatim output of a Meta Muse model (`muse-spark-1.3` or `muse-wonder-1.0`) called through the Meta Model API during a recorded run. The same is true of the machine cards, diagnoses, experiment proposals and hypothesis ledgers in those bundles. Trusted code does not edit, retune or rewrite them.

How to check this for any bundle:

```bash
uv run python scripts/audit_run.py <run_id>
```

Check 6 compares each stored controller byte for byte with the `source_code` field of the model response recorded in `model_calls.jsonl`. Checks 1 and 5 compare each file's sha256 and length with its `controller_v*.meta.json` and its registration event. The `controller_diff_*.patch` files are generated by trusted code from two model-authored files and contain no hand edits.

The baseline controllers in `backend/evaluation/baselines.py` (fixed PID, slow PID, on/off) were written by the project, not by Muse. They are used only for scoring and are never shown to the model.

## Protocol versions

The protocol is what the agent may measure, what it is shown, and the prompts. It was changed four times. Each change was made in response to a measured failure, logged in `docs/IMPLEMENTATION_STATUS.md` (decisions log), and given a new prompt hash. Controllers, scores, scenario seeds and the frozen evaluator were never edited to fit a result. Every version's runs are kept in `artifacts/runs/`.

| Protocol | Prompt hash | Change | Motivating measured failure |
|---|---|---|---|
| v1.0 | `1a84ab41dd365d79` | initial protocol | none |
| v1.1 | `b24d8a294e0ba81e` | up to 4 bounded re-identification experiments on the changed machine before revising; 150-point post-change traces; revision asks for a quantified change | run spark2: repairs under-estimated the added delay (5 to 10 s estimated vs about 20 s) |
| v1.2 | `d9206efcefe117cb` | per-experiment `command_before` and seconds since the command last changed; delay measured from the last command change; after-change experiments up to 40 s under the same envelope | run spark3: a delay of about 22 s measured as 7 to 9 s |
| v1.3 | `0d19650e641cac11` | prompt says the budget counts experiments, not seconds, and that equilibrium needs settled holds; warning about tight integral clamps; trusted `measured_summary` per experiment and per evaluation episode, computed only from measured y and applied u | run spark6 failed G2 on all 5 candidates (equilibrium duty estimated at 0.75, true about 0.58); run spark7 needed 4 candidates |

One gate rule changed: the Gate 3 promotion rule now judges the changed machine only, and reports nominal performance after repair without gating on it. It was decided while no run had passed Gate 3 (decisions log, 2026-11-01). Run spark3's recorded FAILED verdict was not rewritten.

## What is not original

- PID control, on/off control, anti-windup, feed-forward, derivative on measurement, and the other control techniques that appear in the baselines and in Muse's controllers are standard control theory.
- System identification by step and constant-input experiments is a standard method.
- The tank model (inflow from a pump, gravity drain, first-order actuator with transport delay, sensor noise) is a textbook plant.
- Container isolation flags and the rolling-window degradation detector are standard engineering practice.

What this project contributes is the integration: a protocol in which a general-purpose model, blind to the plant's parameters, designs the experiments, writes and revises the controller, and is scored by trusted code it cannot reach, with every step recorded and auditable.
